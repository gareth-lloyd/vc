# Quotation Transmission

Rendering the quote as HTML and sending it to the client, plus the Zoho push that fires on successful send.

## Send quotation to client by email

**ID:** `QUOTATION.TRANSMISSION.SEND_EMAIL`
**Trigger:** Staff clicks "Send Quote" after quote finalised.
**Actor:** Staff (sends from their own SMTP profile — see `01-identity/user-administration.md`).
**Legacy locus:** `ResService.cs:4094-4156` (`SentQuotation` / `SentQuotationNew`).

### Inputs
`QuotationRatesVM` or `EnquireArgs` with:
- `Id` (quotation id), `EnquireId`
- `Email` (recipient), `FirstName`, `LastName`, `Title`
- `ClientDetails`, `QuotationDetails` (line items)
- `Content` (HTML-rendered quotation body fragment from the builder)
- Implicit: `userId` (staff sending)

### Process
1. Read CSS file `quotation-rate-lookup.css` from disk.
2. Wrap content: `<html><head><style>{css}</style></head><body>{Content}</body></html>` (`ResService.cs:4100-4112`).
3. Build `EmailConfig`:
   - `Module = "Sent_Email_Quotation"`
   - `To = client Email`
   - `Subject = "Quotation from Villa Collective"`
   - `Body = wrapped HTML`
4. `EmailService.SentQuoteEmail(emailConfig, userId)` — uses the **staff member's** per-user SMTP profile (so the email "appears" to come from the agent's own address).
5. On success:
   - `EXEC sp_updateEnquireStatus {EnquireId}, {2}` — parent enquiry flips to `Quoted`.
   - Build `VillaQuotationMaster` payload (`ResService.cs:4127-4136`).
   - Call `PushZohoQuotation(args)` — see `INTEGRATIONS.ZOHO.PUSH_QUOTATION_BOOKING`.

### Outputs / side effects
- **Email out:** rendered HTML quote.
- **DB write:** `VillaEnquire.Status = 2`, `UpdatedAt`, `UpdatedBy`.
- **Zoho push:** custom `VILLA_QUOTATIONS` module record with full line-item breakdown (see `11-integrations/zoho-crm.md`).

### Data transformations for storage
- CSS inlined into the email body.
- Dates formatted `yyyy-MM-dd HH:mm:ss` for the Zoho payload.

### Failure modes
- Email service timeout → caught; **status update and Zoho push skipped**. The quote remains `Draft`.
- Zoho API down → quote marked sent locally; Zoho out of sync until manual resync.
- Missing client email → email fails; status not updated.
- Staff member without configured SMTP → falls back to global config (see `EmailService.SentEmail` workflow in `11-integrations/email-delivery.md`).

### Open questions
- Render the HTML email server-side from a template (Django + Jinja or Mjml), not by inlining a CSS file.
- Decide whether the Zoho push should be synchronous (so its failure prevents marking the quote sent) or asynchronous (so a transient Zoho outage doesn't block staff).

### Inputs
